# 预测与线报纪律（唯一权威源）

> 适用范围：本项目所有的线报（`intelligence_archive.md`、`reports.json`）、看板、预测（`predictions.json`）和操作方案。
> 主线由 Gemini 负责。Claude 只做侧评审，按本文件逐条核对，结果写在 `claude_review.md`。
> 用户需要预测。本规则不限制预测本身，只要求预测可以检验、带上概率、按收盘数据打分。

## 一、分工

| 角色 | 负责 | 不做 |
| :--- | :--- | :--- |
| Gemini（主线） | 同步数据、维护并扩展自动爬虫、写线报（向用户输出通俗“人话版”，在档案中保存“量化完整版”）、登记预测、提出方案 | 不给自己的预测打分；不删改侧评审意见 |
| Claude（侧评审） | 核对事实、算术和费率；按收盘数据打分；指出过度笃定的措辞 | 不写主线线报，不登记主线预测，不替用户选方案 |
| 用户 | 决定是否操作、怎样操作 | — |

对评审意见有不同看法时，在下一期线报里写明理由。不要直接改 `claude_review.md`，也不要删除正文中的〔侧评审…〕注释。

## 二、预测：要可检验，要带概率，更要提高实际命中率

1. 线报里每一条关于未来涨跌的判断，都要登记到 `predictions.json`，并在正文里写明它的 ID 和概率，例如“012733 下周收涨（EP12-01，概率 0.55）”。没有登记的判断只能写成“观察点”，不能写成结论。
2. `predictions.json` 只能新增条目，不能修改已登记的条目。脚本会对已登记内容做指纹比对，发现改动会在记分卡里报出来。
3. 字段说明：

| 字段 | 含义 |
| :--- | :--- |
| `id` | “期号-序号”，如 `EP12-01` |
| `report_id` / `made_at` | 出自哪一期、写于何时（精确到分钟；盘中写的要注明） |
| `target` | 6 只持仓的基金代码；或指数：`000001` 上证、`000300` 沪深300、`399006` 创业板指、`000688` 科创50、`000832` 中证转债；或 `PORTFOLIO`（整个组合） |
| `metric` | `return`：相对 base_date 收盘的涨跌幅（%）；`nav` / `close`：收盘净值或点位；`profit`：持有收益（元），只能用于基金或 PORTFOLIO |
| `op` / `value` | 比较符（`>` `>=` `<` `<=`）和阈值 |
| `base_date` / `eval_date` | 基准日和判定日，都按收盘计 |
| `mode` | `at`：判定日收盘时满足才算命中；`any`：窗口内任一交易日收盘满足即算命中 |
| `probability` | 0.05–0.95，不允许写 0 或 1 |
| `statement` | 线报原话 |
| `rationale` | 依据 |
| `base_rate` | 引用 `portfolio_latest.json → risk_context / forecast_signals` 里该标的同期限的历史区间与条件胜率 |
| `falsified_if` | 出现什么结果就说明判断错了 |

4. **提高预测命中率的五条铁律（「量化回测 + 现实新闻子代理」双引擎驱动）**：
   - **铁律一（必选动作）：每期必须派发独立检索子代理（`invoke_subagent`，`TypeName="research"`，`Model="flash"`）全网搜集并深度解读现实主流新闻**：
     - 本地爬虫（`fund_tracker.py`）只负责抓行情数字、A股公告标题和最近十几分钟的滚动电报，**绝不能替代对现实世界主流新闻的深度检索与解读**。
     - 每期写线报和做预测前，**必须**派发 1~2 个 `flash` 检索子代理，主动搜集并交叉核验国内外主流信息源：
       1. **国内权威政经与监管信源**：新华社、央行（公开市场与货币政策）、财政部、全国人大常委会议程与发布会、国家医保局（国谈双目录）、证监会等；
       2. **主流财经媒体与行业深度报道**：财联社、东方财富、第一财经、财新、新浪财经、证券时报等关于今日板块领涨/领跌原因、资金流向与机构调研的深度解读；
       3. **海外市场与产业链巨头动态**：路透/彭博/美股财报纪要、美联储/美债收益率、美国国会与关税/生物安全法案动向、海外映射龙头（英伟达、AMD、Marvell、Lumentum、超微电脑、礼来等）最新财报与指引；
       4. **重仓股公告正文穿透**：针对本地爬虫发现的重仓股公告（如百济神州三季报、恒瑞 FDA 受理、中际旭创/新易盛/海光信息回购或产能指引），由子代理检索具体财务数字与市场正反面解读。
   - **铁律二：用「现实新闻正反证据」修正「历史 K 线条件胜率（`forecast_signals`）」，禁止纯看图算命**：
     - K 线历史回测只知道“过去相似走势下怎么走”，不知道“明天有什么突发大事或政策/财报落地”。
     - **共振加权**：只有当 `forecast_signals` 的历史条件胜率（$\ge 60\%\sim65\%$）与子代理核实的现实基本面/政策催化方向一致时，才作为高把握预测登记；
     - **一票否决（Veto）**：若 K 线显示“超跌反弹胜率高”，但子代理查出该板块刚刚遭遇现实重大利空（如核心客户砍单、财报暴雷、监管收紧），现实新闻拥有一票否决权，严禁盲目抄底预测反弹。
   - **铁律三：严禁盲目猜“暴跌次日立刻 V 反”**：机构高拥挤度重仓股（如光模块、CXO）放量破位后，往往存在 2~3 波“去拥挤化”抛压（如 10/30 大跌后 11/3 再次大跌，直到 11/4 才反弹；012737 在 10/27 大跌后第 6 个交易日 11/4 才回到前高附近）。不要在放量下跌当天去赌 1~2 天后的单点（`mode: "at"`）反转。
   - **铁律四：优先采用高历史条件胜率（Conditional Base Rate >= 60%）的结构性判断**：每次下预测前，必须结合子代理新闻结论与 `portfolio_latest.json` 中的 `forecast_signals`。避免去猜基准胜率只有 50% 的单日正负硬币，多做**有安全垫支撑的区间/缓冲线判断**（如 `110020` 守住触发线）、**大涨超 $1.5\sigma$ 且重仓股分化后的短期震荡消化判断**、以及**给足 5~8 个交易日窗口的触达型判断（`mode: "any"`）**。
   - **铁律五：看清基金底层的真实对冲结构**：
     - `012733`（人工智能）= **海外映射光模块（中际旭创、新易盛，受美股费半/英伟达主导）** + **国产算力与软件（寒武纪、海光信息、芯原股份、科大讯飞、浪潮信息、金山办公，受国内政策与科创板流动性主导）**。两股力量方向一致时才顺势预测单边涨跌；两股力量撕裂对冲时，优先预测窄幅震荡或均值回归。
     - `110027`（安心回报A）= **116.04% 债券（看十年国债 ETF `511260` + 中证转债 `000832`）** + **15.70% 股票**。
     - `012737`（创新药A）= **CXO（药明康德、康龙化成）** + **创新药（恒瑞医药、百济神州）**，高度受美债利率、汇率与医保目录催化影响。
   - 定概率之前先看基准。单只基金 1–5 个交易日的无条件涨跌方向接近五五开。没有强条件胜率与现实新闻共振支撑时，概率写在 0.45–0.65 之间；只有当历史条件胜率与现实新闻催化共振时，才给出 0.65–0.80 的概率。

## 三、打分：只认收盘数据，由脚本判定

1. 运行 `python fund_tracker.py grade`（运行 `sync` 时也会自动打分），结果写入 `prediction_scorecard.md`。这个文件由脚本生成，不要手改。
2. 不得用盘中数据宣布“命中”。正文引用盘中数字时，标注“盘中 HH:MM”。
3. 每期线报开头贴出记分卡汇总：已判定条数、命中率、平均 Brier、声称概率均值与实际命中率。
4. `reports.json` 的 `verification_notes` 只写脚本的判定结果和预测 ID，不写“100% 命中”“完全命中”“一字不差”。

## 四、措辞与双层报告规范（给用户看“人话版”，后台存“量化版”）

1. **双层报告架构（照顾大一/在读大学生“懂得不多、想一眼看懂”的需求）**：
   - **直接发给用户的聊天线报（通俗易懂“人话版”）**：
     - 用大白话、清晰直观的账本和小结跟用户沟通，把晦涩的金融术语翻译成日常语言（例如把“逆回购净回笼”说成“央行今天从市场收回了一点资金”，把“p10~p90 常态区间”说成“平时 10 天里有 8 天的正常波动范围”，把枯燥的涨跌幅换算成“今天回血多少元、离回本还差几块钱”）。
     - 重点回答用户最关心的 4 件事：① **昨天实打实到账赚亏多少、今天盘中大概赚亏多少**；② **今天为什么涨/跌（哪只基金在立功、哪只在挨揍）**；③ **怎么提高接下来的预测准度、未来几天怎么走（带把握概率）**；④ **今天要不要操作、距离下一个免手续费节点还有几天**。
     - **不再附加任何生硬的免责声明套话**。
   - **后台归档文件（`intelligence_archive.md`、`reports.json`、`predictions.json`）**：
     - 继续完整保存所有量化指标、`p10~p90` 历史基准、预测 ID、条件胜率与证伪条件，供后续模型复盘训练与侧评审核验。
2. 硬性禁用。`lint` 会报“硬”，发布前必须清零：
   - 必然、必将、必迎、一定会、肯定会
   - 100% 命中、百分之百、完全命中、精准命中、一字不差
   - 稳赚
   - 无风险、零风险（同业存单写“低风险”）
   - 底部已确认、底部探明、铁底
3. 尽量不用。`lint` 会报“软”，确实需要时要配上数字和常态区间：暴涨、暴跌、暴降、闪崩、至暗、惊魂、外科手术、断腕、止血、左轮手枪、救命、千万不要、立刻、马上、🔥、🚀。
4. 涨跌用数字和常态区间来描述，例如写“012733 -5.06%（近一年单日 p10 为 -3.0%）”，而不是写“暴跌”。只有幅度明显超出 `risk_context` 里的常态区间时，才用“大涨”“大跌”。
5. 发布前运行 `python fund_tracker.py lint intelligence_archive.md --section "第 N 期"`，硬性问题必须为 0。

## 五、方案与规则

1. 方案写成“选项 + 代价 + 风险”。可以给出倾向，但要写明理由和不确定性；不用“最推荐”“千万不要”这类强推或恐吓的说法。最终由用户决定。
2. 列手续费时，同时列出同期限的组合波动区间，即 `risk_context.portfolio` 里对应天数的 p10–p90，让用户能比较两者的量级。
3. 只有费率表或规则上确实有截止时间，才写“X 日前”。费率变化日以 `portfolio_latest.json → fee_calendar` 为准，逐笔费用用 `python fund_tracker.py fees` 计算。
4. 修改 `trigger_rule` 时，在线报里写明“规则变更：原规则 / 新规则 / 原因”，并同步修改 `fund_tracker.py` 里的 `PORTFOLIO_CONFIG`。规则临近触发时，不得不加说明就撤销。

## 六、数据与新信源自动爬取入库

1. **每次发现有价值的新数据来源，必须直接写进 `fund_tracker.py` 的爬虫与 `portfolio_db.sqlite` 数据库（含 `api_registry` 登记）**，以后运行 `python fund_tracker.py sync` 自动拉取存档，不用每次再去全网搜索。
2. 份额只认 `fund_tracker.py` 里的 `LOTS` 账本，数据来自支付宝的确认份额。有新交易就追加一行，不要再用持有金额反推份额。
3. 赎回费率只认 `REDEMPTION_FEES`（天天基金官方费率表，2026-10-31 核对）。基金公告调整费率时，更新这张表并注明核对日期。
4. 线报的结构化摘要写进 `reports.json`，不要再写进 `fund_tracker.py`。
5. 修改任何已有文件之前，先复制到 `_backup/<日期>_<说明>/`。
