# 后台运行规则

- 所有可以放后台跑的命令一律用 `run_in_background: true`，不占用主对话时间：构建、测试、lint、类型检查、安装依赖、dev server、长时间脚本、下载等
- 启动后继续做别的事，命令结束时系统会自动通知；不要用 `sleep` 或反复轮询等结果
- 互不依赖的后台命令（如 lint 和类型检查）在同一轮里一起启动，不要一个等一个
- 需要边跑边看输出（dev server、watch）时用 Monitor 盯着，不要前台阻塞；Monitor 是延迟工具，用前先 `ToolSearch select:Monitor` 加载
- 只有后面的步骤必须依赖这条命令的结果、且没有别的事可做时，才前台运行（如 `git status`、`ls` 这类瞬时命令也直接前台）
- 后台任务失败时：先看输出末尾找原因，不要直接重跑；同一命令重跑后仍失败，按 `model-routing.md` 的「修了 2 次」处理
- 项目里的自检、校验、导出类脚本可以后台跑，但验收结论要等它结果出来再下
- 回复用户之前，确认后台任务都已结束或已汇报，不留没交代的后台进程
- 子代理同理：不需要立刻拿结果的调研/检索任务，以后台方式启动
