# iceppt 风格 PPT

方法来自账号 iceppt（小红书号 94397528789）2026 年 61 篇幻灯片图笔记。来源和剔除情况见 [references/sources.md](references/sources.md)。

## 哪份材料说了算

三层材料讲的是同一件事，精确程度不同。有冲突时，前面的压过后面的。

| 顺序 | 材料 | 内容 | 数值来源 |
|---|---|---|---|
| 1 | [catalog/structure/](catalog/structure/README.md) | 30 张结构卡 + 共用规格（页头、字号、颜色、字体、细节元素） | 像素实测或折算 |
| 2 | [catalog/](catalog/README.md) | 312 页单页原图，按图形类型索引 | 原图本身 |
| 3 | `references/01`–`05` | 文字规则，解释为什么这么做 | 目测估算 |

颜色、字号、页头尺寸只在共用规格里写一次。本文件和 `references/` 里出现的其他数值，都以共用规格为准。

## 版式先说话（Let the layout do the talking）

**含义：能用排版表达的内容，先用排版表达；文字做辅助，但辅助是必要的。** 关系、主次、顺序由形状、大小、位置和颜色承担；文字负责说清图形说不清的东西：口径、原因、数字的含义、下一步。这条不是"少写字"。

1. **先定图形，再写字。** 每个版块先问"这是哪种关系"：多少、对比、流向、变化、构成、取舍。选能直接画出这种关系的图形，文字贴着图形写。
2. **密度向原图看齐。** 一页只放一个图和一句标题，信息量只有原图的三分之一左右，不算完成。具体数字见下面"密度和字数"。
3. **文字要有分工。** 每段文字都应属于下面某一类，否则删掉或改成图形：
   - 结论句：标题下一句，对象 + 动作 + 结果
   - 图上直接标注的数值和名称
   - 批注：写原因和后果，贴着数据点
   - 解读卡：2–3 步，每步一两句
   - 收口条：一句 So what
4. **写了也要靠版式分层。** 主信息、次级说明、补充信息用三档灰度和字号拉开，让人先看到图，再读到字。
5. **模糊测试。** 把截图模糊到认不出字，仍应看得出重点对象、版块划分和阅读方向。

## 重做就是重做

用户说"重做"时，从空白文件开始：重新想每页要回答的问题，重新选结构卡，重写结构和代码。不沿用旧版的页序、版式、配色和代码，不在旧文件上改。旧版只用来确认哪些地方被否定了。

## 工作流程

1. **确认场景**：汇报、述职、周会、面试 case、商赛，还是单页改稿；看的人要靠这几页判断什么。
2. **先写字，后排版**：写三句话（发生了什么、为什么、接下来做什么）；再把每页的结论句写完，只读结论句应能复述整份内容。
3. **每页选一张结构卡**：到 [catalog/structure/README.md](catalog/structure/README.md) 的清单里，按"这页要讲的关系"选。没有合适的卡时，到 `catalog/sheets/<图形类型>.jpg` 看范例总览，选一张原图，先照结构卡的格式自己拆出版块表，再做。
4. **照卡搭骨架**：版块位置、底色、描边照做；每个版块里的文字类型和条数向原图看齐，内容换成自己的；卡里列的细节元素逐个做出来。
5. **检查**：
   - 把原图和自己的截图上下拼成一张图，逐项核对版块数、位置、图形、强调落点、细节元素。
   - 跑 `node tools/layout-check.js <deck.html> <页数>`，看留白和细节密度（只适用于 HTML 输出）。
   - 过一遍文末的自检清单。

要产出 .pptx 文件时，同时加载 `pptx` skill，由它负责文件生成。色值用 [references/design-tokens.json](references/design-tokens.json)，它和共用规格是同一套数。

## 统一规则

下面每条都是对旧规则里互相矛盾之处的裁定。

### 页头和体系

- 作者有两套体系：**绿色体系**（默认）和**酒红咨询体系**（述职、年度汇报类）。两套的页头写法都在共用规格里。一份文件只用一套，不混用。
- 一份汇报里所有页用同一种页头。绿色体系统一用案例页的页头：圆角标题栏 + 黑圆点结论句。用到概念页的结构卡时，保留它的主体版块，页头换成统一的；概念页的定义框可以留，放在结论句下面。
- "概念页 + 案例页成对"只用于讲框架的材料（教学、商赛附录）。汇报不需要成对，直接用案例页的写法。
- 品牌字的位置和样式照原图，文字换成自己的，不写 `@ICEPPT`。

### 颜色和强调

- 色值只用共用规格里的那一套。深色强调只出现在少数小块上：原图里深色面积的中位数约 0.2%，九成页面不到 1.3%。页面主体是白底、浅灰底和少量浅色底。
- **一页一个视线落点。** 落点可以是一个对象，也可以是一组同类对象（如瀑布图里所有的减少柱）。除此之外不再出现第二处同等强度的强调。
- 强调色的意思是"看这里"，不代表好坏。要强调的恰好是负面数据时照样可以用，在图例或标签里写明含义。
- 红色只做 ✗、▼ 和下划线这类小标记。涨跌有固定颜色习惯的领域（如 A 股红涨绿跌），不要用红绿表示涨跌，用深浅或正负号。
- 第二个色相只在一页里要区分两个角色时才用（如哑铃图的两端）。

### 密度和字数

- 版块数照结构卡，一般 4–6 个。
- 汉字数是结果，不是目标。原图多数在 250–450 字一页；结构卡上的"约 N 字"可以上下浮动三成。
- 用检查脚本的两个数判断：留白 60%–79%，细节密度 4.0–6.6。低于下限是太空，补版块和细节元素；高于上限是太挤，先删重复说明，再删最次要的一个版块。
- 正文字号照共用规格（12–13px，约 9–10pt）。只有用户说明要现场投屏、嫌字小时，才放大字号并减少版块。

### 字体

- 用真正有粗体的字体。中文字体栈和英文、数字、衬线的用法见共用规格。
- 运行环境里的中文字体没有粗体时，不要用描边去模拟，在交付说明里写明即可。

### 输出格式

- .pptx：所有元素可选中；图表用原生图表，数据在内置表格里；标题和坐标轴文字分开；不用矩形拼假柱状图。
- HTML：文字是真文字，不是图片；图表由代码里的数据按比例画出；用断言核对派生数字。原生图表那几条不适用。

### 内容

- 第一页放结论，最后一页写清需要对方决定什么。项目本身有边界时（如不能给投资建议），要决定的事限定在边界以内，并在页面上写明边界。
- 标题写结论句：对象 + 动作 + 结果，尽量带数字。
- 单个数字要配基准（上期、目标、行业、随机水平）。
- 页面上每个数字都要有来源；自己算出来的数（差值、占比、倍数）用断言或脚本核对，并写清口径和日期范围。
- 图表按真实数据按比例画。纵轴截断时在图上标出来。
- 批注写原因和后果，不重复图上已经有的数字。

## 自检清单

- [ ] 每页选了结构卡，版块数、位置、细节元素和卡对得上？
- [ ] 和原图上下拼图看过？
- [ ] 留白和细节密度在范围内？模糊后仍看得出重点和版块？
- [ ] 全套只用一种页头、一套色值？
- [ ] 每页只有一个视线落点（一个或一组对象）？
- [ ] 每页标题下有一句结论句，只读结论句能复述全文？
- [ ] 数字有基准、有来源，派生数字核对过，日期范围写准了？
- [ ] 首页有结论，末页写了需要对方决定的事，且在项目边界以内？
- [ ] 没有文字溢出、重叠、被裁切？

## 不要做的事

- 不要只留一个图和一句标题就交。
- 不要把结构卡当图形参考只抄主图，丢掉旁边的批注、解读卡和收口条。
- 不要自己另配一套颜色或页头，除非用户要求。
- 不要编造笔记里没有定义的概念（如"淡人感"）。
- 不要复刻作者的商品宣传页（封面卡、目录页、"附文件"引导）。
- 不要把拼图画布的边距当成幻灯片内边距。
