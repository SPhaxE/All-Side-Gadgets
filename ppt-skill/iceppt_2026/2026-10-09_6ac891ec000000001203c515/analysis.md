# how to把基础变得不基础：让基础分析图形变得“不基础”的7个思路

## 本篇主旨
把信息屋、金字塔、漏斗、循环图、四象限、韦恩图、鱼骨图等基础 diagrams 换一种画法：保留逻辑骨架，对形态做「拆分、展开、拉伸、重组」，让图形成为版式的一部分；形态可变，但支撑、层级、循环、交集关系必须讲清楚，涉及数据比例的部分要准确。

本次只读了 04.jpg 与 05.jpg，两张都是"工具方法页 + 案例页"的整页拼图（单张图内含 3 张幻灯片竖排）。其余 9 张图为跨笔记重复，见"复用说明"。

## 提炼出的设计规则
1. 页面三段式：方法页（定义 → 结构图 → 用法 → 场景）+ 案例页（背景/KPI → 图 → 动作 → 结果），同一模型成对出现，序号（014/015/072/073）和同一套外框统一。
2. 每页标题 = 英文模型名（粗黑大号）+ "- CASE STUDY：中文案例问题"（同行细体较小）；标题下紧跟一条结论句，前置黑色实心圆点，句中包含 2-3 个量化结果（如"58%提升至76%"）。
3. 方法页顶部用圆角描边框装"一句话定义"：加粗下划线小标题 + 2-3 行小字背景，不超过 3 行。
4. 小标题统一用"灰色大号序号 #1/#2/#3 + 粗黑小标题"，把一页内容切成 3-4 块，每块只有一个主题。
5. 指标对比统一写成 "旧值（灰）→ 新值（强调色加粗）"，放在页面顶部或底部的 KPI 条里；单个 KPI 卡内数字不超过 2 个。
6. 图表只对关键对象着色：气泡图 15 个气泡中仅 1 个（目标象限）用绿色，其余全灰；强调色面积控制在版面约 10% 以内。
7. 图与解读卡用编号一一对应（图中象限 1-4 ↔ 右侧卡 1-4；3 Horizons 地图的点 1-9 ↔ 右侧动作 ①-⑨），避免读者在图例和文字之间来回找。
8. 用深浅两种同色系区分硬/软、关键/非关键（Hard S 深绿 vs Soft S 浅绿；关键任务深绿粗条 vs 普通任务浅绿条）。
9. 警示/时间节点（交付日、关键路径终点）单独用红色，是全套里唯一的第二强调色，且只用在竖虚线与菱形上。
10. 结构图保持模型骨架：7S 中心大圆表示共享价值观，外围六圆等距环绕，以细线连接；中心圆实心深绿，外围圆白底绿描边，视觉重心一目了然。
11. 圆内文字三层：英文名（绿，粗）→ 中文名（黑，粗）→ 一行灰色小字说明；层级靠颜色和粗细区分，而不是字号变化过大。
12. 案例页的"诊断图"直接复用方法页的图形，只替换圆内说明文字，保证读者能把方法与案例对上。
13. 虚线框用来标记"结果/重点区域"（3 Horizons 的三个任务框、7S 案例的"项目结果（12个月）"、气泡图象限 2 的绿色虚线框）；实线圆角卡用来装普通信息。
14. 批注用带轻阴影的圆角灰白小框，直接放在图上并以细线指向目标条，不用额外图例。
15. 页面内部大量使用圆角矩形、细线分隔和灰底块，不用重阴影与渐变（只在 3 Horizons 的弧线、批注框有轻微阴影）。

## 出现的思维模型/框架/方法论
- **3 Horizons（三层次增长）**：H1 优化核心业务、H2 转型/培育第二曲线、H3 创新/探索新机会；案例：工业设备制造商以 "守住核心业务+布局AI预测维护"，服务收入占比 12%→28%；呈现方式是 3x3 地图+对角线 + 右侧任务/关键动作清单。
- **McKinsey 7S**：Strategy / Structure / Systems（Hard S）+ Style / Staff / Skills / Shared Values（Soft S），中心为 Shared Values；用法 4 步：明确战略变化 → 检查7个要素是否匹配 → 识别关键断点 → 联动调整组织动作；场景：战略转型、并购整合、组织诊断、增长变革；案例：整合营销广告公司从项目制内耗到续约率 58%→76%。
- **Bubble Chart（战略业务组合分析，类 BCG 矩阵）**：X=相对市场份额，Y=市场增长率，气泡大小=绝对经营利润；四象限含义 Question Marks / Stars / Toxic Tail / Cash Cows；案例：15 个子品牌盘点，得出价值 2 亿美元的品牌剥离与重组。
- **Gantt Chart（甘特图）**：WBS、Time Horizon、Bars、Dependencies、Milestones；关键路径法 CPM + 资源平衡；案例：用关键路径把延期的系统切换拉回正轨；战略行动三招：Reallocation（资源重新分配）、Crashing（关键路径赶工）、Tracking（并行执行妥协/跟踪）。

## 正文金句与方法（来自 note.md）
- 主旨：让基础分析图形变得“不基础”的 7 个思路；信息屋、金字塔、漏斗…等基础 diagrams 也可以换一种画法。
- 核心方法：保留逻辑骨架，再对形态做「拆分、展开、拉伸、重组」。
- ❶ 信息屋 → 展开成版式：屋顶变成目标区，柱子拆成并列信息栏，地基延伸为共享基础层，保留上下支撑关系。
- ❷ 金字塔 → 切开后展开：保留半边金字塔，把每层分界线向右延伸，接上标题和解释，让层级成为排版的一部分。
- ❸ 循环图 → 拉成长回路：把圆环拉成跑道形，或展开成横向流程，再用回流线连接起点，保留循环方向。
- ❹ 漏斗 → 向侧边展开：保留逐级收窄的轮廓，将每个阶段向右展开，留出转化率、流失原因的展示空间。
- ❺ 四象限 → 让内容走出格子：保留坐标与分界线，把内容变成项目标签，重点说明引到图外，还可以加入迁移箭头。
- ❻ 韦恩图 → 换轮廓、放大交集：把圆形换成椭圆或圆角矩形，保留相交关系，将关键交集突出并引出说明。
- ❼ 鱼骨图 → 展开成原因树：调整主干方向，让原因分组水平展开，保留“问题—原因类别—具体原因”的层级。
- 改造基础准则：形态可以变，但支撑、层级、循环、交集的关系要讲清楚；涉及数据比例的部分也要保持准确。

（对应本次读到的页面：04.jpg 中 3 Horizons 的 3x3 地图+右侧任务清单，是"让内容走出格子 / 展开成版式"的做法；05.jpg 的气泡图把四象限的说明引到图右侧的 4 张解读卡，也属于 ❺ 的实例。）
