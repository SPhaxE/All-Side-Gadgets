# 思维模型与框架库及其页面化方式

> 数据范围：61 篇笔记的逐篇摘录（2026-01-13 至 2026-11-09）。
> 证据口径：同一页幻灯片在多篇笔记中重复出现只算一条证据。例如"工业设备商 BAB 8%→25%"页、"Liquid Death 护城河"页、"Nintendo Wii/Switch"页、"Zappos MOT"页、"Southwest 3C"页、"完美日记 AIDMA/AISAS"页，各自只是一页，被反复引用。下面的"来源"写的是笔记日期，只作定位，不代表有多少个独立页面。
> 原始摘录里没有 hex 值，也没有 pt 字号，只有"深绿/浅灰绿/墨绿/酒红"这类色名和大小层级。凡是数值区间，都标注"推断"。

## 一、稳定规则（跨多篇、跨不同页面反复出现）

### R1. 一个模型 = 概念页 + 案例页，成对出现
- 这是本主题最稳的结构，至少 20 篇笔记用到。
- 笔记自己的说法有"每个模型 1 页理论 + 1 页案例解析"（07-09）、"概念页 + CASE STUDY 页"（08-14）、"模型页 + 案例页成对"（08-11、07-23、07-24、07-17）。
- 概念页回答"这是什么、怎么用"。案例页回答"真实公司/真实数据跑一遍是什么结论"。
- 例外：有些模型只有概念页。Scenario Planning（07-24）、Stakeholder 矩阵（07-24）、BAB（08-21）、3C（08-07）、TAM-SAM-SOM、AARRR 都只见概念页。skill 默认输出成对页；只出概念页时要在备注里说明，不能让它冒充已验证的案例。
- 做页顺序（09-04）：先定框架，再填数据，再决定留哪些数据，再写结论句，最后才调图标、间距、颜色。

### R2. 概念页的固定骨架（07-21、10-12、09-15、09-01、08-20 相互印证）
1. 页面顶部：左上粗黑英文大标题（模型名），右上编号/水印（如 `@ICEPPT 012`，仅为模板标识，生成 PPT 时可替换为页码）。
2. 标题下一条圆角"定义胶囊"：首行加粗，格式为 `英文名（中文名）- 一句话价值判断`，下接约 3 行小字释义。
   - 例：`BCG Matrix（波士顿矩阵）- 逼迫管理层做出真正的取舍——不是所有业务都值得投入`（07-21）。
   - 例：`Ansoff Growth Matrix（安索夫增长矩阵）- 企业制定增长战略的标准起点`（07-21）。
3. 左侧主图（占约 55%–65%）：2x2、三圆、链条或曲线。右侧约 35%–45% 放"如何使用"（3–4 步）或"使用要点 / 常见局限"各 3 条。
   - BCG 左约 55% / 右约 45%；Ansoff 左约 65% / 右约 35%（07-21，均为作者拆解的估算）。
4. 图内每格或每个元素的结构：英文名 + 小号中文名 → 一行粗体特征 → 3 条要点 → 典型场景标签（2–3 个圆角描边小标签）。
5. 底部可加一条灰底结论条，例如 Ansoff 的"风险：渗透 < 开发 ≈ 产品开发 < 多元化"（07-21、07-09、09-07）。
6. 内容层面，概念页固定回答三件事：核心问题（Core Problem）、适用场景（Application）、逻辑（Logic）（09-01、08-20、09-15）。

### R3. 案例页的固定骨架（09-07、09-03、10-12、10-29 相互印证）
1. 页眉：框架名 + `CASE STUDY` + 案例标题。
2. 一句结论句：加粗，放在标题栏下。
3. 左约 1/3 为叙事（背景 → 冲突 → 动作），右约 2/3 为主图。右侧或下方放解读卡（09-03、09-07）。
4. 叙事常用"三步"（10-29、09-07）：Step 1 核心命题 → Step 2 拆解逻辑 → Step 3 战略行动。也可写成"现象 → 拆解 → 行动"。
5. 数字要有前后对比或基准：例如 8%→25%、58%→76%、LTV:CAC 6:1、15 分钟 vs 60 分钟（见第三节的案例库）。
6. 案例页的图要换成真数据图。例如 SWOT/TOWS 案例页的象限里填具体措施，不再是定义；BCG 案例页换成气泡图；RCA 案例页换成冰山 + 帕累托。

### R4. 页面标题写成结论句；分析名要改写成听众的问题
- 来源：10-14、10-29、08-21、03-28、05-15、10-12。
- 改写示例（10-14）：
  - "市场分析" → "这个市场，现在还值得进入吗？"
  - "用户画像" → "下一阶段，我们应该优先服务谁？"
  - "护城河分析" → "同样卖饮料，这个品牌凭什么被选择？"
- 每页自问三件事：主题、数据、结论（03-24）。
- 模板占位语也说明这一点："Write one sentence conclusion here"（05-15）、"Conclusion for this page"（04-20）。

### R5. 框架页的信息主次靠四招拉开（10-12）
- 视线落点：用字号、颜色、留白突出最关键的一处。
- 主次拉开：核心判断 > 分析维度 > 补充说明，占比、字重、字号依次降低。
- 位置表达关系：相关的放近，并列的对齐，从属的分组。
- 同类一致：同层级标题、同含义颜色全页统一。
- "Done 版"特征：灰黑、等权重、表格化。"Well Done 版"特征：深绿 + 浅绿、图形化、有层级（10-12、11-05、10-26）。

### R6. 一个强调色 + 灰度打底；颜色即信息（10-23、10-26、08-31、07-21）
- 思维模型页（2026-07 起的"nerdy 绿"系列）：白/浅灰绿底，深绿作轴标签、竖线、对勾、强调，黑色作标题，灰色作说明。
- 一个重点色 + 一个基础色，如"绿+白"（10-26）。重点数据与普通数据的颜色比例约 2:8（10-29）。
- 同一含义的颜色在跨页保持一致（10-23）。
- 若三个平级方案用由浅到深的同色，会被误读为有等级。这时要么改成同色同深，要么在图例里说明（10-23）。
- 色值：digest 只给色名。深绿/墨绿的 hex 请由配色章节统一，这里不另造。

### R7. 版式只有三种底座：左右、三分、上下（10-26）
- 对应关系（10-26，来自作者拆解）：
  - 左右：左问题 + 图，右表格（护城河）。
  - 三分：左/中/右三栏（7S）。
  - 上下：上五列，下对比 + 步骤（SMART）。
- 选择指引（综合推断）：
  - 一图 + 一组使用步骤 → 左右。
  - 三个并列块（现状/诊断/行动，或 S-C-R）→ 三分。
  - 先摆元素再给对比或步骤 → 上下。

### R8. 基础图形要"保留逻辑骨架，改形态"（10-09、10-20）
- 信息屋：屋顶变目标区，柱子变并列栏，地基变共享基础层。
- 金字塔：保留半边，层界线向右延伸，接标题和解释；表达观点时改成"顶部结论 + 下方理由"。
- 循环图：拉成跑道形，或展开成横向流程，加回流线。
- 漏斗：向侧边展开，留出转化率和流失原因；在流失最重的一层拉开间距（10-20）。
- 四象限：让内容走出格子，成为项目标签；加迁移箭头；有数据时引入坐标系。
- 韦恩图：换成椭圆或圆角矩形，放大交集。
- 鱼骨图：改成原因树。
- 底线：形态可变，但支撑、层级、循环、交集关系要讲清楚；涉及数据比例的部分要准确（10-09）。

### R9. 汇报骨架：结论先行，数字说话，末页要决策（07-14、07-16、08-20、08-12）
- 第 1 页放结论；前 30 秒抓不到重点就输了（07-14）。
- 用现成模型装叙事，不要按搜集顺序念（07-16，3C 例）。
- 末页写"需要您拍板的是什么"（07-16）。
- 用具体数字代替形容词，例如"转化率从 3% 提到 4.3%"（07-14）。
- 急活三步（08-12）：先确认决策者关心什么，再定结论和证据，每页先写大标题再往下搭。
- 先洞察后数据（07-28）：先说"用户增长停滞，不是活动少，而是一直在触达同一批人"，再接数据、原因、方案。

## 三、案例页写法规则（跨篇稳定）

1. **案例必须有数**：每页至少 2–3 个硬数字，最好有前后对比。例：8%→25%、58%→76%、28%→36.2%、15 分钟 vs 60 分钟、15 天 vs 90 天、1.0x→7.0x。来源 08-21、07-14、10-12。
2. **案例来源分两类**：知名公司真实事件（Boeing、Zara、Netflix、Zappos、Patagonia、Uber 中国）；匿名化的"某工业设备制造商/某零售连锁/某大厂 PM"。08-06 称后者为"真实/半真实案例"。skill 使用匿名案例时，要在页脚标明"示例数据"，不要冒充真实公司。
3. **案例页的结论句要点出"框架得出了什么"**，不是复述背景。例：SWOT 案例用"S 抵御 T 的平替 + O 做二线城市 D2C"（10-08）；Moat 案例用"品牌文化 + 社群是护城河"（07-31）。
4. **叙事写成"现象 → 拆解 → 行动"或"核心命题 → 拆解逻辑 → 战略行动"**（09-07、10-29）。
5. **反常现象开场更抓人**：销量涨、利润跌（10-08）；门店 +21% / 用户 +18% / 收入仅 +3%（10-19）。
6. **闭环验算**：拆解树必须验证加总（¥428M−¥419M=¥9M，10-19）；漏斗各步转化率的乘积要等于总转化。
7. **以金句收束**，来源多为图内文字，可参考：
   - "战略的本质是取舍"（07-31）
   - "抓大放小，集中整个团队的火力彻底解决这根源问题"（09-20）
   - "客服中心不是成本中心，而是核心的 MOT 制造工厂"（09-20）
   - "用户买的不是产品，而是雇它来完成一项任务"（09-09）
8. **别把概念页写成百科**：概念页保留"适用场景 / 常见局限 / 使用步骤"，不展开学术史。7S、SMART 的历史说明（作者、年份）在 10-26 里存在，但字号最小，作为脚注处理。

1. **模型编号与清单不对应**：09-15 的文字清单列的是 001–020，图片却是 050–096，两者不对应。编号体系（001–100）能否直接用于 skill 的排序没有依据。

3. **同一案例的数字不一致**：
