# 干净 但不是空：气泡图（072）与甘特图（073）的信息密集型"干净"页面

## 本篇主旨
用"气泡图 BCG 式战略盘点"和"甘特图关键路径"两个思维模型，示范数据可视化 PPT 如何在信息密度很高的情况下保持"干净"：浅底白卡片、细线框、单一绿色强调、灰度做背景层。标题"干净 但不是空"即点题：留白不等于信息少，而是靠分区与层级让密度可读。note.md 正文只有标签（数据可视化ppt、思维模型、工作汇报、汇报技巧、高级感ppt 等），没有文字 tips。

### 01.jpg 中：Gantt Chart 073（概念页 / Core Idea）
- 页面角色：方法讲解页（概念 + 示意图）。标题 "Gantt Chart"。
- 定义行：带下划线的 "Gantt Chart (甘特图)" + "- 以时间为横轴、任务为纵轴，全景展示复杂项目进度、依赖关系与资源分配的可视化时间轴。" 下方两行小字说明历史："由亨利·甘特于 1910 年代发明…强制管理者直面任务的并发性与前后依赖关系。尤其是在识别并锁定"关键路径"后，它成为了 PMO（项目管理办公室）监控交付延期风险、动态调度资源的终极仪表盘。"定义和说明装在一个圆角细线外框里。
- 版式：下部左右两栏，左约 38%（Core Idea 文字区），右约 60%（甘特图示意）。
- 左栏结构：
  - 浅绿色细体大字 "Core Idea" 作为区块标题（不加粗，绿色）。
  - 下分三个小节，每节顶部是浅灰底的小标题条："The Core Problem | 核心问题"、"Application | 适用场景"、"Logic | 结构逻辑"。
  - Core Problem 下用三个空心圆点列提问："为什么前端 UI 早就画好了，后端接口却迟迟不能联调？""如果外部供应商晚交货一周，整个项目最终会延期多久？""哪些任务可以同时开工，哪些任务必须排队等待？"
  - Application 下用绿色对勾列表：关键路径分析（Critical Path Method - CPM）"★ 寻找那条决定项目总时长的"最长连续任务链"。在这条路径上，没有任何任务有缓冲时间。"；资源平衡"发现某名核心员工在同一周被安排了 3 个并行任务时，强行拉长甘特图以平滑工作量，避免单点崩溃。"
  - Logic 下是术语 + 解释的键值对列表：WBS（工作分解结构）、Time Horizon（时间跨度）、Bars（时间条）、Dependencies（依赖关系连线）、Milestones（里程碑），各一句"位于 Y 轴左侧…""位于 X 轴，定义…""长度代表耗时，位置代表起止日期""决定了"只有做完 A，才能做 B"""零耗时的检查点，代表阶段性成果的交付"。
- 右栏图表：
  - 小标题"常规甘特任务表"+ 灰色副标"由任务及时间组成"。
  - 表头：左 "任务"，右 "时间/周" 与 W1 到 W12 列标；顶部有绿色小字 "今日" 标记，对应一条绿色竖向虚线（落在 W3 附近）。
  - 行分三组：Phase 1 Requirements & Design（需求与设计）、Phase 2 Development（开发阶段）、Phase 3 Launch（上线部署）；阶段行用深灰色整行底色，任务行（Task 1.1 到 3.3）用白底，行间有浅灰横分隔线。
  - 任务条用浅灰、浅绿圆角条，关键任务 Task 2.1 Backend API 用深绿实心条（视觉重心）；里程碑用深绿菱形（Task 1.3 行与 Task 3.3 行右端）；依赖用细线箭头。
  - 三个带细线引线的白色小气泡批注框（圆角、灰线）：
    - "关键任务条：没有任何容错空间。这条红线上的任何一天延误，都会导致整个项目 1:1 的硬性延期，这是高管唯一需要每日盯盘的区域。"
    - "缓冲浮动区：这些任务即使延期几天，也不会影响项目的最终交付日，有经验的 PM 会优先赠送这里的资源去支援吃紧的战线。"
    - "前置依赖：强制的物理逻辑限制（如：地基没打完，绝对不能建二楼）。它锁死了项目"并发提速"的幻想。"

## 提炼出的设计规则
1. 案例页标题格式固定为 "英文模型名（粗体大字）+ CASE STUDY：中文案例标题（同行细体小一号）"，右上角放编号水印（如 @ICEPPT 072），便于系列化。
2. 标题下紧跟一行"结论摘要句"：前置黑色实心圆点，加粗，一句话包含"方法 + 发现 + 结果（含数字，如 2 亿美元、12 周）"。读者只看这一行就能知道页面结论。
3. 背景/困境用"灰底小标签 + 一句话"两行交代，不写成段落。
4. 左图右文：图表占约 55–60%，右侧放编号卡片或行动清单；右侧文字永远是"特点/措施"或"英文动词名 + 中文副标 + 一句话"的固定三段式。
5. 强调色面积控制在很小范围（约 5–10%）：整页大部分是灰和白，只有"关键"那一处用绿（或红）。气泡图只让一颗气泡 + 一个象限框变绿，其余全灰。
6. 灰度分层表达"次要/待处理"：同一图中，用更深一档的灰底表示"放弃/长尾区域"，用浅灰半透明气泡表示非重点对象。
7. 图表去装饰：气泡图无网格线，仅保留轴刻度与虚线象限分界；甘特图只用细横分隔线，阶段/工作流分组行用整行深灰底。
8. 象限编号用大号浅灰数字置于角落（1 到 4），并与右侧卡片编号一一对应，建立"图—文"映射，无需额外连线。
9. 重点说明卡用主色实线边框加粗，非重点卡保持细灰框，与图中主色圈出的区域形成呼应。
10. 状态符号（对勾/叉）放在卡片右上角，用颜色（绿/红）区分处置方向，比文字更快。
11. 甘特图用批注气泡框（白底、灰细线、引线指向对应条）讲解"关键任务条/缓冲浮动区/前置依赖"，批注文字写成含后果的完整句子，而不只是名词。
12. 关键路径与"交付日/今日"用一条贯穿全图的竖向虚线（绿或红）标注，终点用菱形里程碑。
13. 概念页结构固定为三块：核心问题（用 3 个反问句）→ 适用场景 → 结构逻辑（术语 + 一句解释），再配一张带批注的示意图。
14. 双语标注：英文术语 + 括号中文（如 Task 1.1: User Research（用户研究）），保持 nerdy 风格同时降低理解成本。
15. 三页之间共用同一套底色、卡片圆角、线宽、水印位置，形成"系列感"。

## 出现的思维模型/框架/方法论
- 气泡图战略盘点（BCG 矩阵式四象限）：X = 相对市场份额，Y = 市场增长率，气泡大小 = 绝对利润。案例：消费品集团 15 个子品牌，四象限对应 The Question Marks（高危盲盒，给 12 个月冲刺，份额不到 15% 则止损）、The Stars（明星，100% 倾斜新增产能与营销预算）、The Toxic Tail（剔毒长尾，立即剥离，占用 30% 供应链精力）、The Cash Cows（现金牛，严苛收割，现金流输血给明星）。结论：推导出价值 2 亿美元的品牌剥离与重组计划。注意：卡片排序与象限编号的对应以图上标注为准（图上象限 2 为右上"明星"）。
- 甘特图（Gantt Chart）：横轴时间、纵轴任务；术语 WBS（工作分解结构）、Time Horizon、Bars、Dependencies、Milestones。
- 关键路径法 CPM（Critical Path Method）：找出决定总工期的最长任务链，该链上无缓冲时间。
- 资源平衡（Resource Leveling）：发现个人并行超载时拉长日程。
- 浮动时间（Float / Slack）：非关键任务可延期而不影响交付。
- 项目赶工三招（案例中的"战略行动"）：Reallocation（资源重新分配，从有缓冲的团队抽调）、Crashing（对关键路径追加预算赶工）、Tracking（串行改并行执行，即 fast-tracking，接受返工风险）。案例：合并 Day-1 仅剩 12 周，ERP 联调的关键路径靠这三招拉回。
